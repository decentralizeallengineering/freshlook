# freshlook

[![tests](https://github.com/decentralizeallengineering/freshlook/actions/workflows/tests.yml/badge.svg)](https://github.com/decentralizeallengineering/freshlook/actions/workflows/tests.yml) ![license](https://img.shields.io/badge/license-Apache--2.0-blue)

Escalation to a fresh, independent auditor: a completely independent look at a project, with the emphasis on stopping complexity from growing.

Why: a team that has worked on code for weeks stops seeing its own sprawl. `freshlook` first computes mechanical metrics (no tokens), then runs a headless
`claude -p` audit that sees only the code and a short intent statement. It gets no prior conclusions, no team memory, no instruction files (`CLAUDE.md` and similar
are stripped from the copy) and no hooks (a fresh empty config directory, project settings not loaded). Tools are read-only: Read, Grep, Glob and a few read-only shell commands.

## Install

Python 3.9+, `git`, and for `run` the `claude` command-line tool. Copy `bin/freshlook` onto your `PATH` and keep the `prompts/` directory next to `bin/`
(or set `FRESHLOOK_PROMPT` to another prompt file). No other dependencies.

## Configure

- `FRESHLOOK_MODEL`: default model for `run` (or pass `--model`). `FRESHLOOK_CLAUDE`: path of the `claude` executable.
- Credentials are never read by this tool. The clean config directory has no login, so use one of:
  - export `ANTHROPIC_API_KEY` (or `CLAUDE_CODE_OAUTH_TOKEN` from `claude setup-token`) in the environment; the child process inherits it; or
  - log in once inside a persistent clean directory, `CLAUDE_CONFIG_DIR=$HOME/.freshlook-claude claude`, then pass `--config-dir $HOME/.freshlook-claude` (or `FRESHLOOK_CONFIG_DIR`) on each run.

## Example

```
freshlook metrics ./myrepo                                  # writes ./freshlook/metrics.json and metrics.md
freshlook run ./myrepo --intent intent.md --dry-run         # prints the exact command, calls nothing
freshlook run ./myrepo --intent intent.md --model sonnet    # writes ./freshlook/report-<date>.md
freshlook diff freshlook/report-2026-01-01.md freshlook/report-2026-02-01.md
```

`metrics` reports, all stdlib and no tokens:

- lines of code by top-level directory, lines added per week against commits per week, and the test-to-code ratio;
- **duplicate mechanisms** in two stages: candidates whose names or docstrings share tokens, then confirmation by normalized AST shape
  (identifiers renamed, literals dropped, node-type sequences compared as 4-gram shingle sets; non-Python files use a token-type sequence).
  Definitions with fewer than 30 distinct shingles and generated code (a "generated by" / "do not edit" header, `migrations/`) are never
  confirmed. Clusters are reported as "N ways to do X" with `file:line` for each member, ranked by total lines;
- **growth by top-level directory** from `git log --numstat --summary`: lines added and deleted per week, the new-to-modified file ratio,
  and an **accretion** flag for directories that grow by 50+ lines (and 10%+) in the second half of history while their commit count stays
  flat or falls (at most 1.25x the first half);
- **config surface**: environment variables read, CLI flags, config keys (code reads plus the repo's own `config*`/`settings*`/`defaults*`
  ini, toml, yaml and json files and `.env.example`) and feature flags, each with its locations, plus the counts at up to 6 commits spread
  over history (`--config-history N`, 0 to skip);
- **ways in**: console scripts (`pyproject.toml`, `setup.cfg`, `setup.py`, `package.json` bin), `__main__.py` files and main guards,
  Flask and FastAPI HTTP routes, and systemd `.timer` jobs in the repo;
- Python dead-file candidates from the import graph (console-script targets count as used), each with a confidence that it is really
  unused, and the largest functions;
- **top 10 simplification candidates**: merge a duplicate cluster down to its largest member, or delete a dead file, ranked by lines
  removable times confidence.

`metrics.json` keeps every earlier key and type; the new signals are added as `growth_by_dir`, `config_surface`, `entry_points` and
`simplification_candidates`. Results are hints and can contain false positives.

Duplicate-finder precision, measured on 30 hand-labelled pairs from Django 5.1.4 in `tests/fixtures/dup_pairs` (every pair one that the
old name/docstring rule flags): the old rule is 14/30 = 0.47 precise, the two-stage finder 11/11 = 1.00 at recall 11/14 = 0.79 (the three
misses are real duplicates too short to clear the shape-size floor). On the random part of that sample the old rule's precision is 2/18.
On the whole Django tree, 5422 candidate pairs (functions, classes and files) drop to 134 confirmed, and the 40 reported clusters hold 97 members instead of 722.
The audit prompt is `prompts/audit.md`; it asks for the purpose in 5 lines, the top 10 sources of complexity, what to delete or merge ranked by lines saved per risk,
what the intent asks for that the code does not do, and what a new maintainer would trip on first. `run` audits the committed tree (`git archive HEAD`) or a plain copy.
